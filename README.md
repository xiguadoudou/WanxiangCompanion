## 0.1.18 模块风格与导航修复

阵容模拟、万象资料库统一使用首页的薄荷绿、深色渐变、磨砂卡片、圆角筛选和搜索框；原生工具栏沿用万象弈伴标识，并补齐模块标题、说明与构建署名。移除两套原站外壳的顶部、底部和“更多”导航，取消原导航预留空白。

模块只能由软件侧边栏切换。Vue 路由守卫、链接和 History 限制与 Android 模块归属校验共同阻止站内跳往首页、排行、账号和其他原站页面，保留阵容方案及资料筛选所需的查询参数。离线检查覆盖 320/390/844 像素宽度下的导航隐藏、路由隔离、摆阵、穿戴装备、图片导出和资料库分类；保留原签名覆盖更新及匹配源码附件。

## 0.1.17 本地移植工作室

按仓库所有者确认的原站授权，将模拟器与资料库的组件、样式和完整基础记录移植到软件本地，保留原站棋盘和资料交互。模块代码与数据在 APK 的 `assets/workshop/site.zip` 中，Android 虚拟资源域名只读取本机资源，不打开原站 HTML，也不加载远程可执行脚本。此前 0.1.16 的在线网页包装已移除。

模拟器支持英雄与装备选择、鼠标/触摸站位移动、棋手与天赋、觉醒、备选和敌方棋盘等原站功能；资料库包含英雄、棋手、装备、天赋、效果牌和初始卡包分类、筛选、搜索、详情。基础资料和 268 个头像/图标随软件提供，其他插图按需联网缓存。联网更新只从原站提取字面数据并缓存，不执行下载脚本。

依赖账号/服务器的操作改为本机功能：方案自动保留；“方案”菜单可保存最近 12 个命名方案、复制软件方案码、导入软件方案码或带 lineup 的原站方案链接，以及导出阵容 PNG/横向 PNG。软件方案码以 WXQ1: 开头，**不是游戏内导入码**。图片导出由软件本地 Canvas 与 Android 图库写入实现，无需原站账号。

完全阻断外网的自动化检查已验证本地启动、添加英雄、鼠标和手机触摸移动、装备穿戴、重新打开保留、PNG 导出及资料库六类内容；同步检查已实际取得 85 个英雄、77 件装备及 261 张基础天赋。数据缓存与原签名构建检查通过，具体设备图库保存仍需实机确认。

公开源码包包含本地模块 ZIP、适配代码、完整数据、来源摘要与重建脚本，保留已有依赖许可注释；用户报告的授权不等于重新授予原站源码 MIT 许可。维护说明见 `android/assets/workshop/README.md`。

## 0.1.16 功能侧边栏（历史实现，已由本地模块替换）

左上角 ☰ 打开原生侧边栏，提供阵容推荐、阵容模拟、万象资料库三个入口。模拟器在软件内加载 `https://www.datawxq.com/team-builder`，资料库采用手机入口 `https://www.datawxq.com/h5/database`，支持分类、搜索和详情；这两个模块需联网，页面功能随原站更新。模拟器横屏操作更方便。

在线模块分别延迟创建，在同一次主程序存活期间切换会保留模拟棋盘、资料库搜索和滚动状态，不清空推荐选择。顶部提供侧边栏、刷新和返回推荐；返回键先关闭侧边栏或返回网页历史，再回推荐。网页图片共享现有磁盘缓存；网页本身按服务器规则使用 WebView 缓存，不承诺离线可用。

在线 WebView 不暴露软件的 Native 控制接口，仅允许本数据站 HTTPS 主页面导航；网络、HTTP、HTTPS、超时与显示进程异常提供重试界面。当前以原站在线模块接入，未重写为本地离线模拟引擎；网页分享/导出等能力受原站与系统 WebView 支持范围影响。浏览内置模块仍属于软件内，悬浮窗自动隐藏。已验证原站添加英雄、资料库分类和搜索，以及侧边栏入口、路由隔离、200 次切换的页面复用和原签名构建。

## 0.1.15 简易模式与锁定透传

默认背景不透明度 50%，旧版 88% 默认值一次迁移，其他自定义值保留。原“长条”入口更名“简易”，约 86 dp 高、每列 64 dp，装备图标和名称整体居中，列间不随窗口拉大而扩散。

简易面板右侧小锁启用点击透传，锁定时不能点选、滑动或拖动面板，旁边保留独立解锁小按钮；解锁按钮先显示成功才会启用透传，异常时回退可操作状态。安卓 12+ 按系统限制设置窗口 alpha，补偿背景 alpha，保持 50% 默认背景尽可能一致。高于系统透传阈值的自定义不透明度在锁定时受系统阈值限制，解锁恢复原设置。回主程序、新局或关闭服务会清理锁定。

竖屏图标、完整/简易面板与解锁按钮避开状态栏和导航区域，拖动、启动和旋转均重新校正；横屏保留左右贴边。已验证状态与透明度策略、144 种安全位置、布局对齐与触摸回归，并沿用原签名构建；具体手机的系统窗口交互仍以实机表现为准。

## 0.1.11 GitHub 更新加速

软件版本检查优先使用 GHFast 加速通道，无法连接、超时或返回无效信息时自动切换到 GitHub 官方与 Pages 备用版本资料。APK 下载同样优先加速，再尝试官方地址，每条线路均检查文件大小、SHA-256、包名、版本和原签名。

公开加速服务目前已验证可以读取版本资料和下载与官方摘要相同的 APK，但无法承诺所有地区持续可达。旧版更新检查已失败的手机，需要先[手动通过加速链接覆盖安装 0.1.11](https://ghfast.top/https://github.com/xiguadoudou/WanxiangCompanion/releases/download/v0.1.11/WanxiangCompanion-0.1.11.apk)，之后才会自动使用新线路。加速仅用于公开的软件更新文件，不需要 GitHub 账号或手机全局代理。

版本资料在 `updates/latest.json` 和 `docs/latest.json` 同步保存，发布检查会拒绝二者不一致的版本；以后维护更新时也必须同时更新这两个文件。

- 图片缓存状态可在设置中查看。阵容统计继续联网查询最新结果，保留对应筛选条件的缓存。
- 已通过窗口切换与模拟拒绝恢复、启动回执、缓存重启/过期/断网/并发与容量回归，以及原签名构建。具体故障手机的系统权限与启动器仍需实机验证。

## 下载页面（GitHub Pages）

页面源码位于 [docs/](docs/)，采用深色磨砂与薄荷绿按钮，适配手机及桌面。首次启用：

1. 打开 [仓库 Pages 设置](https://github.com/xiguadoudou/WanxiangCompanion/settings/pages)。
2. 在 **Build and deployment → Source** 选择 **Deploy from a branch**。
3. Branch 选择 **main**，目录选择 **/docs**，点击 **Save**。

GitHub 完成首次构建后，可访问 **https://xiguadoudou.github.io/WanxiangCompanion/**。

网页每次加载优先读取同站 `latest.json`，失败后尝试加速版本资料、已发布 Releases 和官方 Raw，显示版本号、更新内容、加速主下载与官方直连。资料加载失败或禁用 JavaScript 时，下载入口仍指向 Releases 最新版本的固定名 `WanxiangCompanion.apk`。0.1.9 起发布脚本同时上传固定名与版本名 APK，两者内容一致。网页没有账户、无统计脚本，也不保存用户选择。

本仓库连接不包含 Pages 管理权限，首次开关需要仓库所有者设置一次。后续不需要重复开关；发布新 Releases 后，页面读取新版本即可更新，不必逐次修改 HTML。

## 源码与发布维护

Android 源码位于 [android/](android/)，包括 Java 实现、主页面和悬浮窗界面、资源、构建脚本及回归测试。构建方法见 [android/README.md](android/README.md)。后续每次发布 APK，都同步提交对应源码，并在 Releases 提供可直接下载的版本源码 ZIP。

0.1.9 的源码是在已有 Release 上补充的，请使用明确命名的 `WanxiangCompanion-0.1.9-source.zip` 附件；该旧标签自动生成的 “Source code” ZIP 不包含此次新增的 Android 目录。以后在包含源码的提交上创建新版本标签。

1. 修改 `android/` 中的完整实现，更新 Manifest 和 `BuildInfo.java` 的版本号；在私有环境沿用原签名构建 APK。
2. 将正式 APK 放入 `updates/`，更新 `updates/latest.json` 的版本、地址、大小、SHA-256 和更新说明，并复制相同内容到 `docs/latest.json`，与本版源码在同次提交中更新到 main。
3. GitHub Actions 校验 APK 摘要、源码版本和 APK 的全部 assets，生成只包含公开源码的 ZIP，并一同发布 APK、版本资料与源码附件。缺失或不匹配的源码会阻止发布。
4. 每版包含 `WanxiangCompanion-<版本>-source.zip`，并附带固定名 `WanxiangCompanion-source.zip`，可通过 Releases 最新版本下载。`SOURCE.json` 记录对应 APK 摘要和源码文件摘要。

已公开的 APK 和源码附件不自动覆盖；同版本重跑逐字节检查现有文件后跳过。0.1.9 首次补充源码时保留原有 APK、版本资料和更新说明，只增加源码附件。

签名私钥、密码、运行缓存、账号凭据不发布。公开构建默认生成自己的调试签名；只有维护者在私有环境提供原签名才能构建可覆盖官方版本的更新包。仓库不保存用户令牌；发布使用 GitHub 自动提供的短期凭据。
